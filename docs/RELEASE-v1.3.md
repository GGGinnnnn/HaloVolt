# HaloVolt v1.3 — 缓存回退与直读/驱动仲裁

## 新增

### 缓存回退开关

「通用 → 电量读取策略 → 读取失败时使用本地缓存」：

- 开启：读取失败时保留上次成功值，并标注“本地缓存 / x 分钟前”。
- 关闭：读取失败会清空该设备电量，显示“尚未读取”，不把旧值当当前值。
- 只影响显示；历史缓存仍保留在设置中，重新开启后可继续使用。

### 驱动运行提示

- DAREU EK75 在官方驱动运行时显示“官方驱动读取”；关闭驱动后显示“直接 HID”。
- 设备详情会明确当前来源，避免把驱动缓存或上次值误解为实时直读。
- 官方驱动不是必需项；但使用“驱动 App 电量”时，驱动必须保持运行。

### 直读 / 驱动仲裁

EK75 的 65 字节 feature 通道与官方驱动共享。实机测试发现：驱动占用通道时并发直读会返回不一致值。因此采用：

1. 官方驱动运行：优先使用驱动显示值（稳定）。
2. 官方驱动关闭：直接 HID 查询。
3. 两者都不可用：显示缓存（如果缓存回退开启），否则“尚未读取”。

这不是“驱动优先于协议”，而是**同一共享通道的互斥保护**。BLE / HID++ / Nordic 52 等独立通道仍优先直读。

## 为什么不能“把网络上所有协议都加上”

不存在一个可穷举的“全网协议列表”：

- 大部分厂商协议没有公开文档，随固件/型号/接收器版本变化。
- 有些设备只暴露 input-only vendor collection，没有查询通道。
- 有些协议需要驱动握手、登录或厂商私有服务。
- 逆向所有品牌既不可维护，也有法律/兼容性风险。

正确方向是：**标准协议优先 + 已知厂商适配器 + 用户自助规则**。v1.3 先保证缓存/仲裁透明，下一版可做：

1. HID 报告抓取向导（本地，不上传）。
2. 用户自定义 HID 规则（VID/PID、usage、feature report、命令、响应偏移、缩放）。
3. 规则导入/导出与社区共享。

## 自助适配（当前可操作）

1. 打开「调试与诊断」，导出报告。
2. 记录设备型号、VID/PID、raw HID usage（例如 `FF02:0002`、`06:0020`、`FF00:0001`）。
3. 在 GitHub issue 附上报告和型号；有条件的可用 USBPcap / HID 抓包附上报告描述符与报文。
4. 如果设备暴露标准 HID Battery Strength 或 Nordic 52，通常无需改代码即可读取。

> 不建议用 OCR 或网页抓取作为通用方案：驱动 App/网页的控件、登录、WebHID 权限因品牌而异，无法稳定覆盖。
